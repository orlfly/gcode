## Purpose

把实测能力接进 agent：列设备、生成测试计划、执行带安全闸门的测试、拿报告，并在提示词层面禁止编造测量值。

## ADDED Requirements

### Requirement: 实测工具注册
系统 SHALL 向 agent 注册实测相关工具，至少包含：列出仪器与能力、生成/查看测试计划、执行测试并返回报告；每个工具 MUST 用 JSON schema 描述输入。

#### Scenario: 工具可用
- **WHEN** agent 运行时启动
- **THEN** 实测工具已注册且可被调用

#### Scenario: 参数校验
- **WHEN** 以缺失必填参数调用实测工具
- **THEN** 返回指明缺失参数的错误而非崩溃

### Requirement: 带电操作在工具层强制确认
系统 SHALL 在执行任何带电步骤前要求调用方传入用户确认令牌；缺少令牌时 MUST 拒绝执行，并在输出中说明需要用户确认。

#### Scenario: 无令牌拒绝
- **WHEN** 调用执行工具但未提供确认令牌
- **THEN** 不执行任何带电操作，返回需要确认的提示

### Requirement: 测量值不得编造
系统 SHALL 在系统提示词中要求：所有实测数值必须来自工具返回的真实测量结果，MUST 禁止凭估计或仿真值冒充实测。

#### Scenario: 提示词约束存在
- **WHEN** 启动 agent 会话
- **THEN** 系统提示词包含「不得编造测量值」与实测工具的用法

### Requirement: 无仪器时降级不报错
系统 SHALL 在没有任何可用仪器时给出可操作提示，且 MUST 不影响 R0/R1 的生成、ERC 与仿真功能。

#### Scenario: 无仪器
- **WHEN** 没有可用测量设备且用户请求实测
- **THEN** 返回连接/配置提示，其它工具仍可用

### Requirement: 安全约束在工具层不可绕过
系统 SHALL 使超限请求与未确认的带电请求在工具层即被拒绝，MUST 不能通过参数组合绕过。

#### Scenario: 超限不可绕过
- **WHEN** 请求超出电压/电流上限
- **THEN** 工具直接拒绝并说明限制，不尝试执行
