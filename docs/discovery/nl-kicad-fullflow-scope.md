# 范围再扩展：自然语言驱动的 KiCad 设计 + 电路仿真

> 新需求：不只是「KiCad → 激光 G-code」，而是用自然语言直接完成 KiCad 的**电路设计**和**模拟测试**。产品从「制造环节工具」升级为「设计-仿真-制造全链路 agent」。

## 可行性基础（KiCad 官方自动化能力）

KiCad 10 提供了完整的自动化接口，agent 不需要 hack：

| 能力 | 接口 | 说明 |
|---|---|---|
| 文件读写 | `.kicad_sch` / `.kicad_pcb`（s-expression 文本格式） | 结构化、可解析可生成，LLM 友好 |
| 命令行 | `kicad-cli` | headless 导出 Gerber/网表/BOM、跑 ERC/DRC |
| Python API | IPC API（KiCad 9+）+ pcbnew Python | 运行中的 KiCad 或 headless 操作板图 |
| 电路仿真 | 内置 ngspice 集成 + `.wbk` 仿真工作簿 | 可从网表驱动仿真 |
| 元件库 | 标准 symbol/footprint 库 | agent 可检索选用 |

**结论**：技术上完全可行，KiCad 是所有 EDA 里对 agent 最友好的（开源 + s-expression + CLI + Python）。这本身也是选 KiCad 而非 Altium 的最强理由。

## 产品愿景（升级后）

> **「用自然语言设计、仿真、制造电路板」**
> 你说："做一个 LM358 同相放大器，增益 10，测量其频率响应" → agent 建 KiCad 工程 → 加符号连线 → 跑 ERC → ngspice 仿真出波特图 → 修改迭代满意后 → 生成激光雕刻 G-code 打样。

## 机会-方案树（OST）

**期望结果**：电子工程师/爱好者从想法到可制造的 PCB 的时间从「数小时+工具切换」降到「对话级」

```

├─ O1 设计门槛:不会用 KiCad/EDS 的人画不出原理图
│   ├─ S1 自然语言建原理图("加个 10k 上拉电阻") → .kicad_sch 生成/编辑
│   │   └─ E1: 10 个常见电路(分压/放大/滤波/电源)语句化建图实测

├─ O2 设计正确性:画完不知道对不对
```

## 修订后的产品分阶段形态

| 阶段 | 能力 | 交付物 | 依赖 |
|---|---|---|---|
| **P0: 设计** | NL → KiCad 原理图编辑 + ERC 解读 | CLI agent + `.kicad_sch` 读写引擎 | s-expression 解析器、元件库索引 |
| **P1: 仿真** | NL → ngspice 仿真 + 结果解读/建议 | 仿真工作流 + 波特图/波形输出 | P0 + ngspice 驱动 |
| **P2: 制造** | 设计 → 激光 PCB G-code + 预览 | Gerber→G-code + 参数推荐 | 前期 MVP 收敛的内容 |
| **P3: 闭环** | 仿真失败→agent 建议改电路→重仿真 | 迭代式 agent 循环 | P0+P1 成熟 |

**关键顺序判断**：P0/P1（设计与仿真）反而比 P2（制造）更适合先做——纯软件、无硬件依赖、可验证性强、受众更广（不是每个 KiCad 用户都有激光机，但每个用户都要设计和仿真）。

## 自然语言设计的挑战（诚实评估）

1. **原理图生成的正确性**：LLM 直接生成 s-expression 容易出错 → 应采用「结构化中间层」：NL → 网表/结构化描述（agent 强项）→ 确定性代码生成 s-expression
2. **元件库对齐**：「加个运放」→ 选哪个符号？需要 LLM + 库检索 + 用户确认的组合
3. **仿真设置的专业性**：SPICE 仿真配置（DC/AC/瞬态分析、探针选择）专业门槛高，正是 LLM 能发挥的
4. **验证闭环**：ERC/DRC/仿真结果是确定性的 → agent 可以闭环自查（这是和写普通代码最大的不同，电路有物理真值）

## 更新后的目标用户

- **首选**：会编程但电子设计经验有限的工程师（软硬结合、iot 开发者）——NL 设计对他们价值最大
- **次选**：KiCad 老用户（用 agent 提效，如快速搭原型、跑仿真）
- **爱好者的-maker**（激光打样场景）

## 需要你确认的关键决策

1. **阶段顺序**：同意 P0 设计 → P1 仿真 → P2 制造 的顺序吗？（我推荐，理由如上；若你更想先要激光打样可调换）
2. **交互形态**：agent 以 CLI 对话为主，KiCad 侧通过「文件读写 + kicad-cli headless」闭环（用户可随时用 KiCad GUI 打开查看）。不做 KiCad 内嵌插件。可以吗？
3. **仿真深度**：P1 先覆盖模拟电路仿真（DC/AC/瞬态）？数字仿真和混合信号后置？
