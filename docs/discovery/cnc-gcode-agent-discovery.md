# 产品发现：CNC G-code 专业 Code Agent

> 状态：发现阶段（Discovery）。以下为多视角发散 + 关键假设，供讨论后收敛。

## 机会理解

**产品概念**：面向 CNC 加工的专业 code agent —— 像 Copilot/Claude Code 之于软件开发，之于 G-code 编程。

**目标用户**：
- CNC 编程员 / 机械师（手写或半手写 G-code）
- 小型机加工厂（买不起昂贵的 CAM 或 CAM 覆盖不到的场景）
- CAM 用户（需要后处理修改、调试、优化）

**核心痛点**（待验证）：
- G-code 方言碎片化：Fanuc / Siemens / Haas / Mazak 各不相同
- 手写易错，碰撞/过切代价高昂（撞刀 = 损坏主轴或工件）
- CAM 后处理输出的代码难以阅读和微调
- 老师傅经验难以传承

## 竞品粗扫

| 类型 | 代表 | 弱点 |
|---|---|---|
| CAM 软件 | Fusion 360, Mastercam | 贵、重、后处理黑盒 |
| AI G-code 生成网站 | 各类 GPT 包装 | 无专业护栏，不懂机床上下文 |
| 仿真/验证 | Vericut, NCSIMUL | 只验证不生成，价格高 |

**空隙**：还没有「理解机床上下文 + 可验证 + agentic」的专业 G-code agent。

## 三视角发散（每视角 5 个）

### PM 视角（市场契合）
1. **方言感知的代码生成** —— 按机床控制器（Fanuc/Haas/Siemens）生成对应方言
2. **G-code 审查模式** —— 不生成，只做「术前检查」：语法、碰撞风险、行程超限
3. **CAM 后处理解释器** —— 读入任意 G-code，用自然语言解释每段在做什么
4. **刀具寿命/参数推荐** —— 基于材料+刀具推荐切削参数并写入代码
5. **探针/宏程序模板库** —— 探测循环、宏 B 类语句的智能生成

### 设计师视角（体验）
6. **对话式修改** —— 「把进给降低 20%，精加工留 0.1mm 余量」→ diff 视图
7. **2D/3D 走刀可视化** —— 生成后即时看到刀路，低成本预览（区别于重型仿真）
8. **机床配置档案** —— 一次录入行程/刀塔/夹具，所有生成自动遵守
9. **从图纸/照片起步** —— 拍图识别特征，半自动生成程序骨架

### 工程师视角（技术壁垒）
10. **内置 G-code 解析器 + 语义模型** —— 非纯 LLM，机器可验证的语法/几何层
11. **干跑模拟器** —— 内置轻量运动学模拟，agent 闭环自查后再输出
12. **控制器方言 IR（中间表示）** —— 一套语义、多方言编译输出
13. **DNC/机床连接** —— 直接下发到机床（Focas/Ethernet/IP）
14. **程序模板 + 参数化宏系统** —— 家庭作业系列件的程序族管理

## 初步收敛：Top 5（按核心价值 × 验证速度 × 差异化）

| # | 想法 | 为什么 | 关键假设（待测） |
|---|---|---|---|
| 1 | **方言感知生成 + 机床档案** | 差异化核心，通用 GPT 做不到 | 用户愿为「懂我的机床」付费 |
| 2 | **内置解析器 + 干跑模拟闭环** | 安全护栏是专业 vs 玩具的分水岭 | 轻量模拟足以建立信任 |
| 3 | **G-code 审查/解释模式** | 最快落地，老师傅也要检查 CAM 输出 | 现有 CAM 用户有此刚需 |
| 4 | **对话式 diff 修改** | 让 LLM 优势发挥在「改」而非「从零写」 | 用户接受对话式工作流 |
| 5 | **切削参数推荐** | 高频刚需，老师傅经验数据化 | 推荐值足够可信（责任问题！） |

## 最大风险假设（先测这三个）

1. **信任假设**：机械师敢不敢把 AI 生成的代码跑在真机床上？（→ 用审查/解释模式起步可绕开）
2. **责任假设**：AI 生成代码撞刀了算谁的？（→ 干跑模拟 + 免责边界设计）
3. **方言深度假设**：方言差异是否深到通用 LLM 真搞不定？（→ 决定技术壁垒是否成立）
