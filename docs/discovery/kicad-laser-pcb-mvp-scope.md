# MVP 范围收敛：KiCad → 激光制作 PCB 的 G-code Agent

> 范围大幅收窄，这是一次正确的聚焦：从「通用 CNC G-code agent」收敛到「KiCad 激光 PCB 制作场景」。

## 场景定义

**用户旅程（现状）**：
```
KiCad 设计 PCB → 导出 Gerber/Drill 文件 → [断裂地带] → FlatCAM/手动转换
→ G-code → LaserGRBL/GRBL 控制器 → 激光雕刻/切割 → 蚀刻 → 得到 PCB
```

**断裂地带（agent 的机会）**：KiCad 输出到激光 G-code 之间的整段流程。

## 这个场景的特殊性（与通用 CNC 的关键差异）

| 维度 | 通用 CNC | 激光 PCB 制作 |
|---|---|---|
| 输入 | 零件图纸/工艺 | **Gerber + 钻孔文件（结构化数据！）** |
| 危险性 | 撞刀损机 | 低：激光功率过大=烧板，但无机械碰撞 |
| 控制器 | Fanuc/Haas/... 碎片化 | **GRBL/LaserGRBL 高度统一**（方言问题大幅简化！） |
| 用户 | 专业机械师 | **电子工程师/maker（会写代码，懂工具）** |
| 现有工具 | 成熟 CAM | **FlatCAM 老旧难用、流程繁琐** |

**三个原始风险假设的变化**：
1. 信任假设 → 大幅缓解：失败成本低（重雕一块板 vs 撞刀），且用户是工程师群体
2. 责任假设 → 基本消解：无机械碰撞风险
3. 方言假设 → 简化：GRBL 生态统一，重心从「方言」转向「Gerber→刀路语义转换」

## 重新定义的问题（LiC 场景真痛点）

1. **工具链断裂**：KiCad → FlatCAM → LaserGRBL 三件套，配置繁琐、FlatCAM UI 陈旧且基本停更
2. **参数黑盒**：激光功率/速度/遍数与板材（覆铜板厚度、感光层）强相关，新手反复试错烧板
3. **无验证**：生成的 G-code 无法预览实际雕刻效果，试错成本 = 一块板 + 时间

## MVP 方案（收敛后）

**核心循环：KiCad 项目 → 对话式 agent → 可预览的激光 G-code**

1. **KiCad 文件接入**：解析 KiCad 项目（.kicad_pcb / Gerber 导出），理解层叠、板框、走线
2. **Gerber → G-code 语义转换**：隔离雕刻（isolation engraving）、钻孔、板框切割三类操作的 G-code 生成，GRBL 方言
3. **激光参数推荐**：按板材 + 激光功率给出功率/速度/遍数起点（可对话调整）
4. **走刀预览**：SVG/PNG 渲染雕刻路径，代替「上机试错」
5. **对话式调整**：「边界隔离宽度加宽到 0.3mm」「钻孔先打定位点」

**暂不做**（明确 Non-goals）：
- 通用 CNC 铣削 PCB（spindle 路线）
- 其他 EDA 工具（Altium/Eagle）—— 架构留接口
- KiCad 插件集成（先做独立 CLI/agent，后做插件）
- 自动对焦/相机对位等硬件交互

## 目标用户画像

**早早期采用者**：会 KiCad 的电子工程师/maker，拥有二极管激光雕刻机（~300-3000 元档）或小功率 CO2，想快速打样而不想送板厂等 3-7 天。

**核心 JTBD**：当我在家调试电路需要一块快速原型板时，我想在几分钟内从 KiCad 设计得到可靠的激光雕刻程序，这样我不用忍受 FlatCAM 的繁琐流程和反复烧板试错。

## 竞争格局（此细分）

- **FlatCAM**：功能全但 UI 陈旧、学习曲线陡、维护停滞 → 主要替代对象
- **LaserGRBL 光栅模式**：面向图片光栅雕刻，不懂 Gerber 语义
- **JTech/各种插件脚本**：零散脚本，无对话式体验，无参数知识
- **空隙**：没有人做「懂 KiCad 语义 + 懂激光工艺 + 对话式」的 agent

## 关键假设（收敛后再排序）

| # | 假设 | 最便宜的验证 |
|---|---|---|
| 1 | 用户现有的 FlatCAM 流程痛到愿意换工具 | 访谈 5-10 个激光 PCB maker |
| 2 | 参数推荐能显著减少烧板试错 | 用 3-5 种常见板材实测建立参数表 |
| 3 | 用户接受 CLI/agent 形态（vs GUI） | 伪装门测试：landing page 收集意向 |
| 4 | KiCad 文件解析覆盖率足够（多数板子标准双层） | 拿 20 个开源 KiCad 项目实测解析 |
